# 第 2 题：沙盒 × AI 原生 Mod ——「心事邮差」

> 题目：在沙盒（MC / 泰拉瑞亚）、JRPG（宝可梦 / 最终幻想）、动作游戏（影之刃零 / 艾尔登法环）中任选品类，如果引入 AI 原生的 Mod，你想构建什么具体玩法？会吸引怎样的人？怎样做冷启动和发布？

**我选沙盒（Minecraft）。** 在写方案之前，我先在自己做的网页小游戏「余晖站」里，把要加的 AI 玩法做出来并跑了一遍（主要是和沙盒很像）。JRPG 和动作游戏我也各想了一个方向，放在第二节。

- 开发日志、实测数据、调用日志：[notes/](../experiments/q2-ai-native-mod/notes/)
- 余晖站在线试玩：<https://henryhuangsice.github.io/yuhui-station/>（线上是基础版，暂不含「心事邮差」；AI 版需要本地后端，请看上面的 demo 视频）

## 一、一些想法

现在 MC 里的 AI Mod，大部分在做同一件事：**给 NPC 装一张嘴**。AI 同伴陪你挖矿、陪你打怪、陪你聊天，比如 Player2 AI NPC 在 CurseForge 上已经有 25 万以上下载。陪玩当然重要，但这条路已经很挤了，而且它解决的是"想玩的时候没人陪"。

我想解决的是另一种状态：**下了班，什么都不想打，只想有个地方把今天放下。** MC 里有大量这样的人：养老服、建筑服、和朋友慢慢种田的人。

所以我的 AI 原生 Mod 不给 NPC 装嘴，而是**给玩家的现实生活开一个入口**：玩家写下一句真实的烦心事，AI 把它变成游戏里的一件物品、一次跑腿和一封回信。

判断一个 Mod 是不是 AI 原生，我的标准是：**拿掉 AI，这个玩法还成不成立？** 心事邮差不成立：玩家写的可以是任何一句话，手写内容池不可能为每句话都准备一个合适的物件、一个合适的收件人和一封合适的回信。我在 demo 里做了没有 AI 时的手写兜底（4 个关键词模板 + 1 个默认），体验立刻退化成"抽签"，玩家一眼就能看出回信和自己写的话没关系。

这个想法的来源：最开始做余晖站，是受了一款在韩国爆火的山寺题材小游戏的启发。我当时分析过它为什么火：主要面向上班摸鱼的人，入门玩法非常简单，几乎没有上手成本；但也正因为简单，后续很难扩展，玩家玩几天就走了。心事邮差就是我给"怎么留住这类玩家"想的答案。我也清楚，种田、摸鱼类的玩家很难转化成付费，所以这个方向更适合做成**免费、开源的 Mod**，而不是一个要靠它赚钱的独立游戏。但盲盒元素是能够有商业变现的实力的，这类需要好的审美的美工，以及好的研究的产品，这个可以再做研究。

PS.但其实AImod不一定也非得服务于游戏本身，游戏辐射的玩家、主播等等都可以用到AI。最近的GTA6的直播在国内常常被封，做这类AI工具也很合适，帮助开启模糊化处理，通过读内存等提前预告下一步，都可以做到。

## 二、三个品类我都想了，为什么选沙盒

先说两个没选的方向。它们和心事邮差用的是同一套 harness 思路：**AI 只在关键时刻出场，数值和规则交给代码。**

**JRPG（类宝可梦）：AI 模拟对战、AI解说、Nuzlocke。**
1.AI 模拟对战：
劲敌训练家由 AI 驱动。每场对战后，harness 把战斗记录压缩成几行结构化摘要：你用了谁、怎么赢的、他输在哪里。下次相遇时，劲敌会据此调整阵容，开场说一句只属于你们俩的话，比如"上次你用皮卡丘打败了我，这次我带了地面系"。对战数值全部由规则引擎计算，AI 只决定"带谁"和"说什么"。
这和第三节"居民记得你"是同一个记忆机制，只是换了一种情绪：从温柔变成较劲。
2.Nuzlocke（死亡即永别的硬核玩法）+ AI 搭档：你的宝可梦有性格和记忆，阵亡时会有"遗言"，存活久了会对你说话。主要服务直播和情感叙事。
3.AI 解说：给对战加一个实时解说员。工程风险低，适合做视频切片。
我没选它，是因为宝可梦是任天堂的 IP，Mod 和同人的版权风险很高，公开发布只能做原创的"类宝可梦"玩法。

**动作游戏（艾尔登法环一类）：死亡编年史。**
动作游戏对实时性要求太高，让 AI 实时操控敌人做不到，所以 AI 只做"旁路"。每次死亡时，Mod 读取死在哪、被谁杀、用的什么构筑，由一位"老猎人"写一段两三句的传说，比如"他第七次倒在那座桥上，这次至少把盾举起来了"。死得越多，你的编年史越厚，可以一键导出分享卡片。
这里延迟不是问题：死亡画面和跑回原地的那段时间，本来就是空的。这和心事邮差"让邮差说'你先随便走走'"是同一个设计：**把等待放进游戏本来就有的空白里。**
我没选它，是因为这类游戏大多没有官方 Mod 接口，要靠逆向读内存，发布和维护成本都高。

**选沙盒的三个原因：**
1. **门槛低**：做成 MC 服务端插件，玩家不用装任何东西，也不用填 API Key。
2. **没有实时压力**：送信、回信都可以慢慢来。
3. **我已经做出来了**：核心循环在余晖站里跑通了，有数据。

## 三、具体玩法（MC 版）

**核心循环：投信 → 分信 → 送信 → 回信**

1. 村庄里多了一个**邮局**（新方块 + 一个邮差村民）。玩家右键投一句今天的烦心事，一天一封。
2. AI 把这句话变成**一件带名字和描述的物品**，并从村子里挑一个**最适合收下它的居民**。比如：
   - "好久没给家里打电话了" → 「一卷缠绕的耳机线」→ 信号塔的老唐
   - "房租又涨了" → 「漏气的气球」→ 拉面摊老板娘
   - "和最好的朋友吵架了" → 「裂开的陶瓷杯」→ 唱诗班的小乔

   （都是 demo 里模型实际生成的结果。）
3. 玩家带着物品走过去交给他。路上可以顺便干别的，这本来就是 MC。
4. 收件人按自己的性格说两句话，然后给玩家一本**回信**（成书）。回信可以收进箱子，越攒越多。

**第二个小玩法：AI 解签。** 在寺庙或许愿井摇签前，先写下想问的事，AI 写一支只属于这个问题的签（七言四句 + 一句白话解签）。它的作用是让玩家每天有一个回来的理由。

**多人服务器上的玩法：匿名代送。** 你的物品可以由另一个玩家帮你送，送的人只看到「一卷缠绕的耳机线」，看不到你的原话。我刻意不做聊天：陌生人之间只通过 AI 改写过的物品互动，这样不会有骚扰和戾气，又能感觉到"有人替我跑了一趟"。

**长期目标：居民记得你。** 每个居民的信箱里存着收过的你的物品。他们会慢慢形成一段关于你的记忆，比如"上个月你送来的那只漏气的气球，我补好了"。这一步还没做进游戏，但它决定了玩家会不会玩一个月以上。（我在第 1 题里，正是拿"居民记得你"当作测试任务，让五个 harness 去实现它。）

## 四、我在 demo 里学到的（也是 MC 版的 harness 设计）

我原本以为难点是"让 AI 写得好"，实际做下来发现，难点是**让它稳定地按规矩写**。

**1. 写在 prompt 里的规则只是"建议"。**
我在 prompt 里写了"不要复述玩家原话""物件只能是比喻关系"。批量测试 13 次，模型第一次就完全合规的只有 9 次。它会把"房租又涨了"变成"涨价的房租单"，签诗也会写成每行 8 个字。

后来我把规则写进了代码：服务端校验每一个字段，比如收件人必须在白名单里、物件不能出现原话里的词、签诗必须恰好 7 个汉字。不合格时，把**具体哪里不合格**告诉模型，让它重写，最多 3 次。

改完后 13 次全部合格：4 次重写里，3 次一次改对，1 次两次改对。比起把 prompt 写得更长，"校验 + 具体反馈 + 重写"更有效。

这和第 1 题的结论是同一件事：**规则要写在代码里，不能只写在 prompt 里。**

**2. 多样性和准确性要取舍。**
一开始工作类烦恼几乎都派给"加班大厦的林工"。我加了"避开最近收过信的两位居民"之后，收件人从 2 个人分散到 6 个人；但有时也会把最合适的人挤掉。这个取舍应该交给玩法决定，而不是交给模型。

**3. 延迟是设计问题，不只是工程问题。**
生成一封信的中位耗时约 4.8 秒，慢的时候超过 10 秒。我没有做加载动画，而是让邮差说"班车跑一圈的工夫就分好，你先随便走走"。玩家走开了，等待就不存在了。在 MC 里，这段时间就是玩家走到收件人那里的路程。

**4. 免费模型最大的问题是"能不能用"，而不是"写得好不好"。**
我用的是智谱的免费模型：最新的 `glm-4.7-flash` 实测频繁返回"访问量过大"，还出现过一次 40 秒没有响应。所以我做了模型备用链（一个不行自动换下一个），最后再用手写内容兜底。**AI 失败时，游戏绝不能卡住。**

**5. 必须有一道安全阀。**
玩家写下的是真实情绪。遇到明显的危机表达，内容不会进入游戏，也不会发给模型，而是直接给出心理援助热线。这一条不能交给模型临场判断。

**MC 版怎么落地：**
- **做成服务端插件**（Paper / Fabric 服务端），模型调用全部在服务器上完成，**玩家不需要自己填 API Key**。要求玩家自己配 Key 是 AI Mod 最大的劝退点；放在服务端以后，服主装一次，全服都能玩。
- **成本可控**：每封信约 700 token。免费模型成本为零；换成付费模型（按 Claude Opus 5.5 的价格估算），一封信大约 1 美分以内，再加上"一天一封"的限额。

## 五、会吸引什么人

| 人群 | 为什么会来 | 我怎么验证 |
|---|---|---|
| **下班后想放松的玩家**（核心） | 不想再被任务和数值追着跑，想有个地方把一天放下 | 看"第二天还回来投信"的比例 |
| **养老服 / 建筑服的服主**（渠道） | 服务器需要"有人味"的日常内容，留住老玩家 | 服主安装后，服内每天投信的人数 |
| **情感向、治愈向的主播**（放大器） | "观众投心事，我在游戏里替他们送信"本身就是一档节目 | 主播自发做的视频数量 |
| **AI 和 Mod 开发者**（共建者） | 居民、物件风格、校验规则都是可以替换的数据 | GitHub 上的 PR 和自定义居民包 |

我的判断是：**真正的用户是第一类，但第一批用户会从第二、三类来。** AI 同伴类 Mod 靠"AI 发疯"的名场面传播，这个 Mod 靠的是**回信截图**。一封写得刚好的回信，就是最好的传播素材。

## 六、冷启动与发布

**原则：先有内容，后有玩家；先打服主，再打玩家。**

| 阶段 | 时间 | 做什么 | 看什么数据 |
|---|---|---|---|
| 0. 原型 | 已完成 | 在余晖站里验证核心循环，跑批量测试，录 demo | 校验通过率、生成耗时（已有） |
| 1. MC 最小版 | 第 1～2 周 | 只做邮局 + 3 个居民 + 回信书；和 10 个朋友在一个服里玩一周 | 一周内每人投信次数；有没有人主动截图回信 |
| 2. 预热 | 第 3 周 | 把最好的 10 封回信做成图卡，发小红书、B 站动态、X；同时开等待名单 | 图卡收藏率；等待名单人数 |
| 3. 种子服主和主播 | 第 4 周 | 邀请 5～10 个养老服服主和治愈向主播先装，提供免费额度和一位专属居民 | 装了以后是否每天都有人投信；主播是否自发出视频 |
| 4. 正式发布 | 第 5 周 | Modrinth + CurseForge + GitHub 开源同时发布；国内发 MC 百科和 B 站视频；海外发 r/Minecraft、r/feedthebeast；把 harness 部分单独发 Hacker News（Show HN） | 首周下载量、Star 数 |
| 5. 社区共创 | 之后每周 | 开放"自定义居民包"（性格 + 擅长接住的烦恼 + 说话方式）；每周评选"本周最好的一封回信" | 社区投稿的居民数量；7 日留存 |

几个关键细节：

- **内置分享**：回信一键导出成带游戏截图的卡片。原话默认不显示，玩家自己决定要不要附上。
- **双线发布**：MC Mod 的主战场在海外（Modrinth、CurseForge、Reddit、YouTube），国内在 B 站、MC 百科和 QQ 群。两边的内容形态不一样：海外更适合发"harness 怎么做的"技术帖，国内更适合发回信图卡和治愈向视频。
- **最重要的指标不是下载量，而是"第二天还回来投信的人"**。这个玩法的价值在于每天一封；如果玩家只投一次，就说明它只是一个新奇玩具。

## 七、风险和我没把握的地方

- **重复感**：回信写多了会有套路。一部分可以靠更好的模型解决，但更根本的是"居民记得你"和社区居民包，这两点我还没验证。
- **多人服务器里的恶意输入**：AI 时代本来就要防提示词注入，多人游戏更是如此。有人会试图让 AI 生成不当的物品名。服务端校验能拦住格式问题，内容层面还需要加过滤和服主管理工具。
- **情绪内容的边界**：游戏不是心理咨询。我的原则是 AI 只负责"接住和变轻"，不给建议；危机内容不进入游戏。这条线需要更多真实玩家测试。
- **商业化**：前面说过，这类玩家很难付费。Mod 本身免费、开源；如果需要付费额度，应该做在服务端的托管服务上，向服主收费，而不是向玩家收费。
