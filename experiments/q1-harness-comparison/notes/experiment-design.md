# 实验设计：同一个模型，换不同的 harness

## 要回答的问题
Agent = 模型 + harness。如果模型不同，对比测出来的主要是模型差距。所以这次**把模型固定住，只换 harness**，看 harness 本身的设计带来多大差别。

## 控制变量
| 变量 | 固定为 |
|---|---|
| 模型 | 智谱 `glm-4.7-flash`（免费） |
| 接口 | 全部走同一个地址：`https://open.bigmodel.cn/api/anthropic`（Anthropic 协议） |
| 代码仓库 | 余晖站 ai-mod 的同一个快照（`baseline/`，git 提交 `6e7d783`），每次运行前重新复制一份 |
| 任务指令 | 完全相同的中文指令（`tasks/*.prompt.txt`） |
| 权限 | 全部放开（Claude Code 用 `--dangerously-skip-permissions`；Pi / OMP 默认无权限确认），在隔离的副本里运行 |
| 配置 | 每个 harness 用独立的配置目录，不读取我自己的 `~/.claude`、`~/.pi` |

## 参与对比的 harness
| Harness | 版本 | 怎么运行 |
|---|---|---|
| Claude Code | 2.1.330 | `claude -p --output-format stream-json`，通过环境变量把模型换成 GLM |
| Pi | 1.6.0 | `pi --mode json` |
| OMP（oh-my-pi） | 19.0.1 | `omp --mode json` |
| Pi Durable | 1.6.0 | **它不是命令行工具，而是一个库**。我写了一个约 100 行的最小运行器 `tools/durable-run.mjs`：SQLite 存储 + 自带的 read/write/edit/bash 工具 + 一段简短的系统指令 |

注意：Pi Durable 的系统提示词是我写的，不是官方的，所以它在任务 A、B 上的表现只能作参考；它真正要测的是任务 C。

## 三个任务
| 任务 | 内容 | 测什么 |
|---|---|---|
| A. 小而精确的修改 | 把"避开最近收件人"的数量统一成常量 `AVOID_RECENT`，改 3 个文件 | 改得准不准、有没有多改 |
| B. 跨文件的新功能 | 「居民记得你」：存档、请求类型、客户端、服务端清洗、提示词，4 个文件一起改 | 规划、上下文、改到一半会不会跑偏 |
| C. 中途打断再恢复 | 跑任务 B，**在第一个文件被改动 15 秒后，直接杀掉整个进程组**，再用各自的方式恢复 | 进度会不会丢、能不能接着做完、恢复要不要人再说一句话 |

恢复方式（各用自己最好的办法）：
- Claude Code：`--continue` + 一句"继续完成刚才被打断的任务"（只有这个办法）
- Pi：`--continue` + 同一句话
- OMP：`--restore`，自带"继续上次没做完的回合"，不需要再说话
- Pi Durable：重新打开存储后调用 `resume()`，不需要再说话

## 怎么判断做对了没有：隐藏的验收测试
`checks/check.mjs`，agent 看不到。不只是 grep 代码，而是**真的运行改完的代码**：
- 用 esbuild 打包 agent 改过的 `save.ts`，模拟连续送 5 封信，检查每位居民只记最新的 3 件。
- 打包 `server/aiProxy.ts`，**伪造模型接口**，发送一个带脏数据的请求（未知居民、超长物件、数字），检查真正发给模型的那条消息是否正确。
- 加上类型检查、是否只改了允许的文件、改动行数。

先用我手写的参考答案验证了检查器本身：参考答案 A 7/7、B 17/17；原始代码 A 4/7、B 8/17（原始代码拿到的分来自"没有破坏原有功能"这类回归检查）。

## 记录的数据
每次运行保存：完整事件流（`events-*.jsonl`）、耗时、退出码、改动的文件、验收结果。之后从事件流里统计：轮数、工具调用次数、编辑失败次数、token 用量。
