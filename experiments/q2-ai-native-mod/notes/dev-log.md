# 开发日志：给余晖站接入 AI 原生 Mod

代码：`yuhui-station` 仓库的 `ai-mod` 分支（本地）。截图：`answers/media/q2/screenshots/`。

## 2026-11-21 · 第一版：心事邮差 + AI 解签

### 做了什么
- **心事邮差**：找站长老周投一句烦心事 → AI 把它变成「一件小物件 + 一位收件居民 + 一次跑腿」→ 送到后收件人写一封回信。一天一封。
- **AI 解签**：摇签前可以写下想问的事 → AI 写一支专属签（等级 + 七言四句 + 白话解签）。不写就是原来的随机签。

### Harness 设计（为什么这样做）
| 问题 | 做法 |
|---|---|
| API key 不能进浏览器 | Vite 开发服务器里加一个本地代理 `POST /api/ai`，key 只在 `.env.local` |
| 模型输出不可控 | 要求输出 JSON；服务端统一校验：收件人必须在 10 个居民白名单里、签诗必须 4 行、各字段有字数上限。不合格就不显示 |
| 任何失败都不能卡住游戏 | 没 key / 超时 / 拒答 / 格式不对 / 断网 → 一律退回手写内容，界面标注来源 |
| 生成有延迟 | 用"老周分信"的等待来掩盖：投完信先去逛，几秒后提示分好了 |
| 心理危机内容 | 关键词命中时不进游戏、不发给模型，直接给出心理援助热线 12356 |
| 成本 | 每天限一封信、一支签 |
| 可复盘 | 每次调用写入 `logs/ai-trace.log`：模型、耗时、token、结果（ok / invalid / refusal）、原始输出 |
| 换模型 | 代理层抽象出 provider：智谱 GLM（免费）和 Claude 都能接，用 `.env.local` 切换 |

### 测试记录
- 无 key 时全流程走手写兜底：截图 01–06。
- 危机关键词 → 返回 `safety`，不调用模型。
- 非法请求 → `bad-request`。
- 打包产物中没有 key。

## 2026-11-21 · 第二版：接入智谱 GLM（免费）实测

### 改动
- 代理层支持两个模型供应商：**智谱 GLM**（免费，`.env.local` 填 `ZHIPU_API_KEY`）和 **Claude**（`ANTHROPIC_API_KEY`），`AI_PROVIDER` 切换。
- **模型备用链**：默认 `glm-4.5-flash → glm-4-flash-250414`，前一个被限流 / 超时 / 5xx 就自动换下一个。
  - 起因：最新的免费模型 `glm-4.7-flash` 实测频繁报 `1305 该模型当前访问量过大`，另有一次 40 秒无响应；`glm-4.5-flash` 约 1 秒返回。
- **原话复述检查 + 一次重写**：AI 第一版输出出现了"这是'房租又涨了'变的价签"，违反了 prompt 里"不要复述玩家原话"的规则。
  - 只靠 prompt 约束不住，所以在服务端加了检查：输出里出现玩家原文中任意连续 4 个字，就判为不合格。
  - 不合格时把原因附在消息后面让模型重写一次；还不合格就退回手写内容。
  - **这是一个很典型的 harness 结论：规则写在 prompt 里只是"建议"，要靠代码校验才变成"约束"。**

### 实测数据（`trace/ai-trace-2026-11-21.jsonl`）
| 指标 | 数值 |
|---|---|
| 成功调用 | 8 次，全部通过校验 |
| 耗时中位数 | 约 4.8 秒（最快 1.7 秒，最慢 32 秒，慢的那次是先撞上限流再换模型） |
| 平均 token | 约 700 / 次 |
| 限流 / 超时 | 8 次（主要发生在 `glm-4.7-flash` 和连续快速请求时） |

结论：
- 免费模型的**可用性**比质量更成问题，所以备用链和兜底不是锦上添花，而是必需品。
- 3～15 秒的延迟被"班车跑一圈的工夫就分好"的设计完全吸收，玩家感知不到在等 AI。

### AI 生成样例
| 玩家写的 | 物件 | 收件人 | 回信 |
|---|---|---|---|
| 周末又被叫去加班，计划好的旅行又没了 | 一张褪色的地图 | 林工 | 工作像潮汐，退了还会来。下次一起看日出吧。 |
| 和最好的朋友吵架了 | 断线的风筝 | 林工 | 风筝断线时，风其实想告诉你，换个角度看风景。 |
| 方案又被退回了，第三次 | 退回的方案稿 | 林工 | 方案总在退回的路上，就像我们总在下班的路上。要不要一起喝杯热茶？ |
| 房租又涨了 | 涨价的房租单 | 老板娘 | 今晚给你煮碗热汤面，加个蛋。 |

| 所问 | 签 | 解签 |
|---|---|---|
| 下周的答辩能顺利吗？有点紧张 | 上签 · 站台灯光照晚钟 / 班车平稳向前行 / 薄荷清香消紧张 / 月色温柔伴你行 | 答辩如班车到站，稳稳当当 |

### 观察到的问题（下一步可以改）
- **收件人偏科**：工作类烦恼几乎都派给林工，连"和朋友吵架"也派给了他。可以在 prompt 里给出近期已派过的人，或者在代码里做轮换。
- **物件有时太直白**：如"涨价的房租单"，只是换了个说法。可以把"原话检查"从 4 字放宽到 2 字的关键词。
- **签诗不严格是七言**："站台灯光照晚钟"符合，但校验只限制 5～9 字。可以收紧。

## 2026-11-21 · 第三版：修三个质量问题

### 改动
| 问题 | 只改 prompt 不够，所以代码也改了 |
|---|---|
| 收件人偏科（工作类都给林工） | ① 给每个居民写明"擅长接住"的烦恼类型（如老唐：想念远方的人；玄青道长：假期被占用）。② 游戏记住最近收过信的 2 个人，请求时一起发给服务端；如果模型还是选了他们，判为不合格 |
| 物件太直白（"涨价的房租单"） | 从玩家原话里提取两字词（去掉"的了又被"这类虚词组合），物件里出现任何一个就判为不合格 |
| 签诗不是严格七言 | 校验从"5～9 字"收紧为"恰好 7 个汉字、无标点" |

另外，校验器不再只回答"合不合格"，而是**列出具体哪里不合格**（例如"物件直接用了原话里的词「电话」"），原样反馈给模型，最多重写 3 次。

### 批量测试
脚本：`yuhui-station/scripts/eval-mail.mjs`，10 封固定心事 + 3 个固定问签，模拟连续投信（带上最近收件人）。结果：`trace/eval-2026-11-21-v3.json`。

| 指标 | 第二版（4 封信） | 第三版（10 封信 + 3 支签） |
|---|---|---|
| 最终通过 | 4/4 | 13/13 |
| 收件人分布 | 林工 3、老板娘 1 | 6 个不同的人：林工 2、老板娘 2、吴阿姨 2、阿甘 2、小乔 1、老唐 1 |
| 连续两封给同一个人 | 有 | 0 次 |
| 物件直接用原话的词 | 2/4（退回的方案稿、涨价的房租单） | 0/10 |
| 第一次就合格 | — | 9/13；重写 1 次合格 3 个；重写 2 次合格 1 个 |

**校验器拦下的 5 次不合格**（重写后都合格了）：
- "最近每天凌晨三点醒"：第 1 版原样引用「凌晨三点」，第 2 版物件用了「凌晨」。
- "好久没给家里打电话了"：物件用了「电话」。
- "体检报告出来了"：原样引用「体检报告」。
- "这次面试能过吗"：4 行签诗全是 8 个字。

**结论：** 小模型对 prompt 里的硬规则遵守率不高（13 次里 4 次违规）；但只要把错误原因具体地告诉它，基本一次就能改对。**"校验 + 具体反馈 + 重写"比把 prompt 写得更长更有效。**

### 新样例
| 心事 | 物件 → 收件人 |
|---|---|
| 方案又被退回了，第三次 | 折角的纸飞机 → 林工 |
| 房租又涨了 | 漏气的气球 → 老板娘 |
| 和最好的朋友吵架了 | 裂开的陶瓷杯 → 小乔 |
| 好久没给家里打电话了 | 断了线的风筝 → 老唐 |
| 工资发了，还完信用卡就没了 | 空钱包 → 老板娘 |

### 仍然存在的问题
- **匹配还不够准**："周末加班、旅行泡汤"本该给玄青道长，却给了阿甘；"凌晨三点醒"本该给小陈，却给了吴阿姨。原因是"避开最近收件人"的规则把最合适的人挤掉了。这是**多样性和准确性之间的取舍**，可以改成"只避开上一位"。
- 重写会增加延迟：一次重写大约多 3～5 秒，好在被分信的等待掩盖了。

## 2026-11-21 · Demo 视频

`answers/media/q2/demo-心事邮差与AI解签.mp4`（1280×720，约 75 秒，真实调用智谱 GLM 生成，没有剪辑或替换内容）。

**录制方式**：脚本 `yuhui-station/scripts/record-demo.mjs` 用本机 Chrome（无界面模式）自动操作游戏、加字幕，再用 ffmpeg 合成。好处是**可重复**：改了 prompt 或校验规则后，同样的输入再录一遍就能直接对比。

**镜头内容**：标题 → ① 找老周投心事 →  ② AI 分信 → ③ 送到收件人 → ④ 回信 → ⑤ 问签 → ⑥ 专属心签 → 结尾卡（AI 原生的含义 + harness 要点）。

**本次生成的内容**：
- 心事"好久没给家里打电话了" → 「一卷缠绕的耳机线」→ 老唐（信号塔）→ 回信"我把你的电话系在风筝上，风会替你传递问候。"
- 问签"下周的答辩能顺利吗？有点紧张" → 上签：班车驶过站台前 / 便利店灯照安心 / 薄荷味缓解紧张 / 月亮升起答案现；解签"答辩如班车到站，自然停靠"。

**录制中踩的坑**：
- 第 1 版：对话时镜头在玩家正后方，主角的帽子挡住了 NPC；传送时镜头会飞过整个星球。
- 第 2 版：改成侧面 3/4 视角，传送时黑场过渡；但老周站台的顶棚会把镜头推近。
- 第 3 版：老周换到另一侧取景；寺庙给镜头多留 1.6 秒稳定。采用这一版。
- 不同次录制生成的物件不同（明信片、耳机线、听筒都出现过），这正是 AI 原生的特点：同一句心事，每次都是新的。
